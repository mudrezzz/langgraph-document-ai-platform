# Support

## 1. Where to ask questions

- Technical questions about usage/extension: open a GitHub Issue.
- Bugs and regressions: open a GitHub Issue with reproduction steps and expected behavior.

## 2. What to include in an issue

1. Version/commit SHA.
2. Runtime profile (`APP_RUNTIME_PROFILE`, `APP_ASYNC_PROVIDER`).
3. Reproduction steps.
4. Actual behavior and expected behavior.
5. Logs/stack trace (without secrets).

## 3. Security issues

For vulnerabilities, do not publish sensitive details in a public issue. Use the process in `SECURITY.md`.

## 4. SLA and response expectations

This project is maintained on a best-effort basis. For critical production incidents, keep your own operational fallback plan.

## 5. Contributor feedback and updates

For contributor-experience feedback and periodic progress updates, use:

- `FEEDBACK.md`
- `docs/project_update_template.md`
