# Onboarding Feedback Tracker

Use this file as a running log for contributor, evaluator, and maintainer
feedback about onboarding friction. Keep entries short, specific, and linked to
the issue or pull request where follow-up work is tracked.

## Feedback Log

| Date | Source | User type | What they tried | Where they got stuck | Suggested fix | Priority | Linked issue/PR |
|---|---|---|---|---|---|---|---|
| YYYY-MM-DD | GitHub issue, PR review, discussion, call, or direct message | Contributor, evaluator, maintainer, integrator, or user | Short description of the workflow attempted | Specific missing step, unclear term, failing command, or decision point | Concrete documentation, tooling, or process change | P0, P1, P2, or P3 | #issue or #PR |

## Priority Guide

| Priority | Meaning |
|---|---|
| P0 | Blocks setup, contribution, release, or a stable public contract path. |
| P1 | Causes repeated onboarding confusion or prevents completing a common workflow. |
| P2 | Improves clarity, navigation, examples, or maintainer process. |
| P3 | Nice-to-have wording, polish, or future follow-up. |

## Entry Checklist

- Keep one row per observed problem.
- Prefer links to the source discussion over long summaries.
- Record the user's actual goal, not only the page or command they touched.
- Link follow-up work once an issue or pull request exists.
